# 방명록·게임 기록 Supabase 연동 구현 계획서

## 1. 목표

현재 브라우저의 `localStorage`에만 저장되는 다음 데이터를 Supabase에 저장하여, 다른 기기와 브라우저에서도 동일한 데이터를 볼 수 있게 한다.

- 방명록 작성 내용
- 테트리스 게임 점수 및 랭킹

기존 페이지 디자인과 게임 동작은 유지하고 데이터 저장·조회 계층만 Supabase 기반으로 교체한다.

## 2. 현재 상태

### 방명록

- 대상 파일: `guestbook.html`, `guestbook.js`
- 저장 위치: `localStorage`
- 저장 데이터: 닉네임, 메시지, 작성 시각
- 현재 브라우저에서 작성한 글만 확인 가능

### 테트리스 랭킹

- 대상 파일: `tetris.html`, `tetris.js`
- 저장 위치: `localStorage`
- 저장 데이터: 닉네임, 점수, 제거한 줄 수, 저장 시각
- 현재 브라우저에서 저장한 기록만 순위에 표시

## 3. 구현 범위

### 3.1 Supabase 연결 설정

- 정적 GitHub Pages에서 사용할 Supabase 브라우저 클라이언트를 추가한다.
- Project URL과 Publishable key를 별도 설정 파일에서 관리한다.
- Secret key 및 `service_role` 키는 브라우저 코드와 저장소에 넣지 않는다.
- 설정이 누락되거나 네트워크 연결에 실패하면 사용자가 이해할 수 있는 안내 문구를 표시한다.

### 3.2 방명록 연동

- 페이지 진입 시 Supabase에서 최신 방명록을 조회한다.
- 작성 폼 제출 시 닉네임과 메시지를 Supabase에 저장한다.
- 저장 성공 후 새 글을 목록 맨 위에 즉시 표시한다.
- 중복 제출 방지를 위해 저장 중에는 제출 버튼을 비활성화한다.
- 로딩, 성공, 실패 상태를 화면에 안내한다.
- 기존 HTML 이스케이프 처리를 유지하여 사용자 입력이 스크립트로 실행되지 않게 한다.

### 3.3 게임 랭킹 연동

- 페이지 진입 시 Supabase에서 점수순 랭킹을 조회한다.
- 게임 오버 후 닉네임, 점수, 제거한 줄 수를 저장한다.
- 점수가 같으면 제거한 줄 수와 먼저 등록된 시각을 기준으로 순위를 결정한다.
- 저장 성공 후 현재 순위와 TOP 5 목록을 갱신한다.
- 로딩, 성공, 실패 상태와 연결 설정 오류를 표시한다.
- 게임 진행 로직과 키보드·모바일 조작은 변경하지 않는다.

## 4. 데이터베이스 설계

### `guestbook_entries`

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| `id` | `bigint` | 자동 생성 기본 키 |
| `name` | `varchar(18)` | 작성자 닉네임 |
| `message` | `varchar(180)` | 방명록 메시지 |
| `created_at` | `timestamptz` | 서버 기준 작성 시각 |

검증 규칙:

- 공백만 있는 닉네임과 메시지 금지
- 닉네임 1~18자
- 메시지 1~180자

### `game_scores`

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| `id` | `bigint` | 자동 생성 기본 키 |
| `player_name` | `varchar(10)` | 플레이어 닉네임 |
| `score` | `integer` | 최종 점수 |
| `lines` | `integer` | 제거한 줄 수 |
| `created_at` | `timestamptz` | 서버 기준 저장 시각 |

검증 규칙:

- 공백만 있는 닉네임 금지
- 닉네임 1~10자
- 점수와 줄 수는 0 이상의 제한된 정수
- 랭킹 조회용 복합 인덱스 추가

## 5. 보안 정책

두 테이블 모두 Row Level Security(RLS)를 활성화한다.

로그인 없는 공개 홈페이지라는 특성에 맞춰 다음 권한만 허용한다.

- `anon`, `authenticated`: 조회 허용
- `anon`, `authenticated`: 정해진 입력 컬럼에 한해 추가 허용
- 수정 및 삭제: 허용하지 않음
- `id`, `created_at`: 브라우저에서 임의 지정하지 못하도록 컬럼 권한 제한

추가 고려사항:

- 공개 쓰기 기능은 자동화된 스팸에 노출될 수 있다.
- 실제 스팸이 발생하면 CAPTCHA와 Supabase Edge Function 기반 요청 제한을 후속 적용한다.
- 게임은 브라우저에서 실행되므로 개발자 도구를 통한 점수 조작을 완전히 막을 수 없다. 이번 구현은 개인 홈페이지용 캐주얼 랭킹을 기준으로 한다.

## 6. 변경 예정 파일

| 파일 | 변경 내용 |
| --- | --- |
| `guestbook.html` | Supabase 스크립트, 연결 상태 안내 영역 추가 |
| `guestbook.js` | 로컬 저장을 Supabase 조회·추가 로직으로 교체 |
| `tetris.html` | Supabase 스크립트, 글로벌 랭킹 문구 반영 |
| `tetris.js` | 로컬 랭킹을 Supabase 조회·저장 로직으로 교체 |
| `supabase-config.js` | Project URL과 Publishable key 설정 |
| `supabase-schema.sql` | 테이블, 인덱스, 권한, RLS 정책 정의 |
| `SUPABASE_SETUP.md` | Supabase Dashboard 설정 및 배포 절차 설명 |

Python 관련 파일과 기존 홈페이지의 다른 페이지는 변경하지 않는다.

## 7. 구현 순서

1. Supabase 테이블과 RLS 정책을 정의하는 SQL 파일을 작성한다.
2. 브라우저용 Supabase 연결 설정 모듈을 추가한다.
3. 방명록 조회·작성 로직을 Supabase로 교체한다.
4. 게임 랭킹 조회·저장 로직을 Supabase로 교체한다.
5. 로딩·오류·저장 중 UI 상태를 연결한다.
6. 정적 분석과 브라우저 테스트를 수행한다.
7. Supabase 프로젝트 정보 입력 및 배포 절차를 문서화한다.

## 8. 검증 항목

### 방명록

- 데이터가 없을 때 빈 상태가 정상 표시되는가
- 새 글이 Supabase에 한 번만 저장되는가
- 새로고침 후에도 작성한 글이 남아 있는가
- 다른 브라우저에서도 같은 글이 보이는가
- 최대 글자 수와 공백 입력 검증이 동작하는가
- HTML 또는 스크립트 형태의 입력이 안전하게 표시되는가
- 네트워크 실패 시 작성 내용이 사라지지 않고 재시도할 수 있는가

### 게임 랭킹

- 페이지 진입 시 랭킹이 점수순으로 표시되는가
- 게임 오버 전에는 점수를 저장할 수 없는가
- 한 게임의 점수를 중복 저장할 수 없는가
- 저장 후 현재 순위와 TOP 5가 갱신되는가
- 동점 정렬 규칙이 일관적인가
- 다른 브라우저에서도 같은 랭킹이 보이는가
- Supabase 연결 실패가 게임 자체의 실행을 막지 않는가

### 보안 및 배포

- RLS가 두 테이블 모두 활성화되어 있는가
- 공개 사용자가 데이터 수정·삭제를 할 수 없는가
- Secret key 또는 `service_role` 키가 소스에 포함되지 않았는가
- GitHub Pages 배포 환경에서 CDN과 Supabase 요청이 정상 동작하는가
- 모바일 화면에서도 폼과 랭킹 UI가 유지되는가

## 9. 완료 기준

- 방명록과 게임 기록이 Supabase에 실제 저장된다.
- 새로고침, 다른 브라우저, 다른 기기에서도 동일한 데이터가 조회된다.
- 저장 중·성공·실패 상태가 사용자에게 명확히 표시된다.
- 기존 디자인과 테트리스 플레이 기능에 회귀 문제가 없다.
- 최소 권한 RLS 정책과 설정 문서가 함께 제공된다.

## 10. 구현 전에 필요한 정보

실제 연결을 완료하려면 다음 두 값이 필요하다.

- Supabase Project URL
- Supabase Publishable key (`sb_publishable_...`)

이 두 값은 공개 브라우저 앱에서 사용하는 값이며, 데이터 보호는 이 문서에서 정의한 RLS 정책으로 처리한다. Secret key는 필요하지 않다.
